## 1. 背景・課題・提供価値

### 1.1 社会的背景と課題
1. **働き方の不可逆な変化**: コロナ禍以降、リモートワーク／ハイブリッド勤務が定着し、「毎日都心へ通勤する」ことを前提とした従来の住宅選び（駅徒歩・沿線・主要駅アクセス重視）と、実際のライフスタイルにミスマッチが生じている。
2. **住宅選択指標の不備**: 賃貸・不動産情報サービスでの評価軸は「家賃・駅徒歩・間取り・築年数」に偏重しており、「日中ずっと家とその周辺で過ごす人」にとっての暮らしやすさ（騒音、緑地、ワークスペース、地域コミュニティ）を測る指標が存在しない。
3. **既存ランキングメディアの問題点**:
   - 評価根拠（データソース・計算式）がブラックボックスである。
   - ユーザー個人の働き方や価値観に合わせて評価軸の「重み付け」を変更できない。
   - データが更新されず鮮度が低い。

### 1.2 リモートワーカーの課題・ニーズ（仮説）
- **静寂性**: 在宅勤務中やオンライン会議中の騒音（幹線道路沿い・線路沿い等）が気になるが、内見だけでは判断しにくい。
- **リフレッシュ性**: 仕事の合間に気分転換できる場所（公園、緑地、散歩コース）が身近にあるか分からない。
- **サテライト環境**: 家で集中できない日の避難場所（サテライトオフィス、図書館の学習席、コワーキングスペース）の有無が不透明。
- **アクセス性**: 週1〜2回のたまの出社が負担にならない距離感か。
- **地域コミュニティ**: 職場で人と会わない分、身近な地域でのつながりやコミュニティ活動の機会があるか。

### 1.3 オープンデータによる解決アプローチ
上記課題を解決する各種データ（大気、交通量、緑被率、公園、サテライトオフィス、図書館、地価、NPO法人等）は、東京都および各自治体によって**オープンデータとして既に個別公開**されている。  
本プロダクトは、これらバラバラに存在するデータを「リモートワーカーの暮らしやすさ」という明確なレンズを通して**市区町村単位に横断集計・統合スコア化**することで、これまでにない住まい選びの指標を提供する。

## 4. システムアーキテクチャ・技術スタック仕様

### 4.1 全体アーキテクチャ方針
本プロダクトは**「完全フロントエンド完結・バックエンドレス（Serverless Static Architecture）」**を採用する。
- データの事前加工（データパイプライン）はPythonスクリプトで行い、静的JSON（`municipalities.json`）を出力。
- Webアプリケーションは静的ファイル（HTML/CSS/JS/JSON）としてホスティング。
- スライダー操作時のスコア再計算および地図の色替え処理は、すべて**クライアントサイド（ブラウザ内JavaScript）で完結**させることで、サーバー維持コストをゼロにし、超高速なレスポンスを実現する。

```
[原データ (オープンデータ CSV/GeoJSON/API)]
       │
       ▼ (Python ETL パイプライン)
[raw/ → interim/ → spatial_join → score.py]
       │
       ▼ 生成
[municipalities.json] (静的アセット)
       │
       ▼ Fetch (初回ロード時)
[フロントエンド (Next.js / MapLibre GL JS)]
       │
       ▼ スライダー操作（クライアントサイド高速計算）
[ブラウザ内計算] ──(setFeatureState)──> [WebGL高速地図再描画 (60fps)]
```

### 4.2 フロントエンド技術スタック

| レイヤー                 | 採用技術                                                           | 選定理由・役割                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **フレームワーク**       | **Next.js (App Router)** <br>*(Static Export: `output: 'export'`)* | コンポーネント指向開発、ルーティング構造管理、ビルド最適化。SSG化によりGitHub PagesやVercelで無料ホスティング可能。               |
| **地図エンジン**         | **MapLibre GL JS** <br>*(via `react-map-gl` or direct wrapper)*    | **WebGL描画による圧倒的高速性**。オープンソース（MIT）で無償。後述の `setFeatureState` により大量ポリゴンの瞬間色塗り替えが可能。 |
| **UIライブラリ**         | **Tailwind CSS + shadcn/ui**                                       | モダンで洗練されたデザインコンポーネント。スライダー、ダイアログ、タブ等の迅速な実装。                                            |
| **モバイルボトムシート** | **Vaul (Drawer component)**                                        | スマホ表示時に地図を邪魔しない滑らかなスワイプ式ボトムシートを提供。                                                              |
| **データ可視化**         | **Recharts**                                                       | 6軸レーダーチャートや自治体比較グラフの描画。レスポンシブ対応。                                                                   |
| **URL状態管理**          | **nuqs** (Next.js State Manager)                                   | スライダーの重み（`w=2,1.5,1...`）や選択中の自治体コードをURLクエリに双方向リアルタイム同期。                                     |

### 4.3 地図高速描画ロジック（MapLibre GL JS × feature-state）

従来方式（Leaflet等でのGeoJSON再読み込み）ではスライダー移動時の再描画で遅延（カクつき）が発生する。本システムでは **MapLibre GL JS の WebGL feature-state 機能** を使用し、DOM操作やGeoJSONの再生成なしにGPU上で色を切り替える。

#### 実装アプローチ:
1. 地図初期化時に、東京都区市町村の基本ポリゴン GeoJSON を Vector/GeoJSON Source としてロード。
2. ユーザーがスライダーを操作した際、ブラウザ内で全自治体の `score` を再計算（計算時間 < 5ms）。
3. 計算結果を `map.setFeatureState({ source: 'tokyo-boundaries', id: code }, { score: calculatedScore })` で流し込む。
4. Style Specification の `fill-color` に `['interpolate', ['linear'], ['feature-state', 'score'], ...]` を設定。
5. **GPUが200msデバウンスで瞬時に色を再塗布（60fps維持）**。

## 5. スコアリングアルゴリズム仕様

### 5.1 全体方針 & スコア計算式
- **6つの評価軸**（各軸 0〜100点に正規化）で評価。
- ユーザーが各軸の重み $W_i \in [0.0, 2.0]$ （初期値 $1.0$）を設定。
- 総合スコア $S_{total}$ は以下の加重平均式で算出：

$$S_{total} = rac{\sum_{i=1}^{6} (S_i 	imes W_i)}{\sum_{i=1}^{6} W_i}$$

- **透明性の担保**: ブラックボックス化を防ぐため、算定根拠・計算式・元データ・最終更新日を画面上に明示。

### 5.2 データ正規化パイプライン（ETL処理）
1. **単位あたり換算**: 各指標の自治体間規模差（面積・人口）を標準化するため、**「1km²あたり」**または**「人口1万人あたり」**の指標値に変換。
2. **外れ値処理（Winsorizing）**: 上下5パーセンタイル（5% / 95%）でクリッピング処理を行い、都心部や極端な離島等の外れ値によるスケール圧迫を防ぐ。
3. **Min-Max Scaling**: 全自治体中の最小値を0、最大値を100とするスケーリングを実施。
4. **指標反転（Invert）**: 「騒音」「PM2.5」「地価」など数値が低いほど望ましい指標は $100 - Score$ で反転。
5. **軸内統合**: 同一軸内に複数指標が存在する場合、指標スコアの単純平均（将来的に加重平均拡張可）を軸スコア $S_i$ とする。

### 5.3 6軸の定義と指標構造

#### 軸1: しずけさ（Quiet）— 住環境の静寂性・大気質

| **PM2.5**        | 大気測定局の年間平均値            | 自治体内の測定局平均     | 低いほど良（反転） |
| **幹線道路密度** | 緊急輸送道路の総延長 / 自治体面積 | 空間結合（Spatial Join） | 低いほど良（反転） |

- **基本情報**: 自治体名、総合スコア、東京都内（全62区市町村）中での総合順位。
- **レーダーチャート**: 選択した自治体の6軸スコア（青線）と、東京都平均（グレー破線）を重ね合わせて表示。
- **指標内訳・データ分布（アコーディオン形式）**:
  - 各軸を展開すると、各構成指標の実測値（例: PM2.5 `9.8 μg/m³`）を表示。
  - 都全体における位置付けを示すミニ箱ひげ図（Box plot）またはプログレスバーを添える。
  - **出典情報表示**: データセット名、提供組織、カタログサイトURL、データ最終更新日を必ず明記。
- **アクション**: 「比較リストに追加」ボタン。

### 6.4 画面3: 比較モード（`/compare?codes=13104,13208`）

- データの欠損がある場合は `value: null` かつ `status: "no_data"` とする。決して **0 で埋めない**。

## 9. 実装コード仕様（参照用）

### 9.1 地図高速色替え（MapLibre GL JS × feature-state）実装例

```typescript
// hooks/useScoreMap.ts
import { useEffect } from 'react';
import type { Map } from 'maplibre-gl';

interface WeightParams {
  quiet: number;
  refresh: number;
  workspace: number;
  commute: number;
  cost: number;
  community: number;
}

export function updateMapScores(map: Map, municipalitiesData: any[], weights: WeightParams) {
  if (!map || !map.isStyleLoaded()) return;

  const totalWeight = Object.values(weights).reduce((a, b) => a + b, 0);

  municipalitiesData.forEach((m) => {
    const { quiet, refresh, workspace, commute, cost, community } = m.base_scores;
    
    // 加重平均スコアの算出 (0 - 100)
    const weightedSum =
      quiet * weights.quiet +
      refresh * weights.refresh +
      workspace * weights.workspace +
      commute * weights.commute +
      cost * weights.cost +
      community * weights.community;

    const finalScore = totalWeight > 0 ? Math.round((weightedSum / totalWeight) * 10) / 10 : 0;

    // WebGL Feature State を更新 (再レンダリング不要でGPU色塗り替え)
    map.setFeatureState(
      { source: 'tokyo-municipalities', id: m.code },
      { calculatedScore: finalScore }
    );
  });
}
```
