## 2. 提出作品（プロダクト・サービス）の概要

### 2-1. 取り組んだ課題の種類 `必須`

> 自由課題

### 2-2. 作品名（サービス名・プロダクト名） `必須`

> Remotelife Tokyo


### 2-3. サービスの詳細 `必須`

> RemoteLife Tokyo は、東京都のオープンデータをもとに、リモートワークのしやすさで都内53市区町村（23区・多摩地域）を比較できる地図サービスです。しずけさ・いきぬき・しごとば・くらしのコスト・つながりの5つの軸で各自治体をスコア化し、地図の色分けとランキングで示します。5軸の重みはスライダーで変えられ、「静かさ重視」「コスト重視」など自分の優先度に合わせて順位が即座に組み替わります。自治体を選べば、スコアの根拠になった指標の実数値と出典まで確認できます。


### 2-4. 着目した課題・背景 `必須`

> コロナ期を境にリモートワークという働き方は都内を中心に定着化しています。リモートワーカーには、通勤を前提とした従来の働き方にはなかった悩みがあります。日中も家にいるため近隣の騒音が仕事に直接響く、人と会う機会が減って孤独を感じる、仕事とプライベートを切り替える場所がない、といったものです。住む場所を変えれば和らぐ悩みですが、既存の物件情報や自治体紹介は通勤の利便性や家賃を中心に組み立てられており、「静かに働けるか」「気分転換できる場所があるか」「家以外に作業できる場所があるか」という観点で地域を比べる手段がありません。その結果、リモートワークを前提に住む場所を選びたい人が、判断材料を持てずにいます。


### 2-5. 課題・背景の解決方法 `必須`

> 東京都のオープンデータを用いて、前項の悩みに対応する5つの軸で都内53市区町村を評価します。騒音には「しずけさ」（自動車交通騒音）、孤独感には「つながり」（NPO・社会教育事業）、切り替えの場には「しごとば」（サテライトオフィス・図書館）、気分転換には「いきぬき」（公園・緑と水辺・PM2.5）を対応させ、これに「くらしのコスト」（地価）を加えた5軸を、それぞれ順位に直して100点満点で示します。軸の重みはスライダーで変更でき、自分が何を優先するかによって順位が組み替わります。

## 3. 技術詳細

### 3-1. 技術選定の理由 `必須`

> データ加工にはPython（pandas,GeoPandas）。CSVとShapefileの両形式を扱い、ShapefileについてはGeoPandasの空間結合を用いて、点・線・面データを自治体区域に重ね合わせて集計する処理を実装しました。データの取得から正規化、自治体別集計、欠損補完、スコア化までのパイプラインを構築し、出力は単一のJSONファイルに統一しました。フロントは Next.js の静的エクスポート／TypeScript／Tailwind CSS。バックエンドを持たず、重みの再計算が通信なしでブラウザ内で完結します。地図は GeoJSON を SVG で描画し、APIキー不要・軽量にしました。


### 3-2. 生成AI等の活用方法 `任意`

> 実装補助に Claude Code を使用しました。「欠損を0で埋めない」「自治体コードは5桁の全国地方公共団体コードで統一する」といったプロジェクト規約を CLAUDE.md としてリポジトリに置き、生成されるコードが規約から外れないようにした点を工夫しました。オープンデータの前処理では自治体名の表記ゆれ・文字コード・単位の不統一など実データ固有の判断が多いため、生成された処理はそのまま採用せず、原データと出典に当たって結果を検証しています。
