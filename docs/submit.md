## 3. 技術詳細

### 3-1. 技術選定の理由 `必須`

> データ加工は Python（pandas／GeoPandas／Shapely）。配布形式が CSV と Shapefile で、点・線・面を自治体ポリゴンへ座標結合する処理が中心のため、GIS 処理が標準で揃う点を重視した。取得→正規化→座標結合→欠損補完→スコア化は連番スクリプトと Make で再現可能にし、成果物は JSON 1本にした。フロントは Next.js の静的エクスポート／TypeScript／Tailwind CSS。バックエンドを持たないため運用コストがかからず、重みスライダーの再計算も通信なしでブラウザ内で完結する。地図は GeoJSON を SVG で描画し、APIキー不要・軽量にした。


### 3-2. 生成AI等の活用方法 `任意`

> 実装補助に Claude Code を使用しました。「欠損を0で埋めない」「自治体コードは5桁の全国地方公共団体コードで統一する」といったプロジェクト規約を CLAUDE.md としてリポジトリに置き、生成されるコードが規約から外れないようにした点を工夫しました。オープンデータの前処理では自治体名の表記ゆれ・文字コード・単位の不統一など実データ固有の判断が多いため、生成された処理はそのまま採用せず、原データと出典に当たって結果を検証しています。
