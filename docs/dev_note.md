## 2026-08-12 オープンデータの実査とURL確定

東京都オープンデータカタログのCKAN API（`/api/3/action/package_show`）で全件のライセンス欄とリソースURLを引き、実ファイルにHTTPリクエストを投げて取得できることまで確認した。
その結果を `data/src/datasets.py` に反映し、`make ingest` で22ファイル取得・失敗0。

### 判定の訂正 — 統計年鑑は要許諾ではなかった

当初「統計年鑑は issues ページからのリンク先が `www.toukei.metro.tokyo.lg.jp` でカタログサイト外なので、③（要許諾→ダミーデータ）に該当しうる」と整理していたが、**これは誤り**だった。

統計年鑑はカタログサイトにデータセットとして登録されており（例: `t000003d2000001012` 東京都統計年鑑 令和5年 1 土地・気象）、CKAN上のライセンスは `CC-BY-4.0`。
**判定の基準はリソースの実ファイルがどのドメインに置かれているかではなく、カタログに掲載されているかどうか。** 実体が `toukei.metro.tokyo.lg.jp` や `zaimu.metro.tokyo.lg.jp` にあってもルール①が適用される（D11・D14・D15なども同じ形）。

面積・人口をダミーデータで進める必要はない。

### 差し替えたもの

| | 当初の想定 | 差替後 | 理由 |
|---|---|---|---|
| D16 | 東京都統計年鑑（土地・気象 / 人口） | 東京都の人口（推計） | 統計年鑑は最新が令和5年と古い。人口推計なら地域コード・人口・**面積(km2)**・人口密度が1ファイルに揃い、当初の2本立てが1本で済む |
| D15 | 東京の労働力 統計データ | 令和２年国勢調査による東京都の昼間人口 | 「東京の労働力」は都全体の集計で区市町村別の内訳がなく、昼夜間人口比率を作れない |

どちらも53自治体を全件カバーしていることを確認済み。
D16は月次更新でURLの年月部分が変わるので、更新するときはカタログで最新のデータセットIDを取り直すこと。

### 不採用にしたもの

- **自動車騒音の常時監視結果** — カタログ経由で辿れるのは目黒区（BODIK）など個別自治体の公開分のみで、53自治体分は揃わない。区市町村データ（④）なので規約の個別確認も要る。しずけさは交通量（D2・D3）と幹線道路密度（D18）で代理する。
- **エコロジカル・ネットワークマップ** — ライセンスは `CC-BY-4.0` で問題ないが、配布物14件がすべてPDF地図。GISデータも数値表もなく指標化できない。

### 追加したもの

- **D18 緊急輸送道路（建設局）** — 「幹線道路密度＝都道の総延長 ÷ 面積」を出そうとしたが、都のカタログに都道そのものの線データがない。国道・都道の主要路線で構成される緊急輸送道路ネットワークが最も近いので代理データとして使う。CC BY・カタログ掲載で条件面の問題はない。

### D4・D13 の個別条件

どちらもカタログ上のライセンス欄が「その他」で、CC BY 4.0 の一括表示から外れている。
D4 の「利用に当たっての注意事項」PDF を読んだところ、大半は精度に関する注意（概略位置である、原典の精度が施設ごとに異なる、属性の面積とポリゴン面積が一致しない等）で、二次利用そのものは妨げていない。

ただし1点だけ制限がある。

- **「宅地化農地」「市街化調整区域内農地」の2レイヤは使わない。** 国土地理院長の承認を得て作成した東京都地形図（S=1:2,500）を使用しており、引用には著作権法上の手続きが別途生じる。
- 使うのは `01_kouenryokuchi.zip`（公園・緑地等）と `03_jurinchi.zip`（樹林地）。

### D5 のコース数の数え方

コースが1件1リソース（KMLのZIP）としてカタログに登録されている。実体を1本も落とさずに、`package_show` のJSON1本でコース数を自治体別に集計できる。
リソースURLのファイル名先頭6桁がチェックデジット付きの団体コードで、その先頭5桁が自治体コードにあたる。

```
.../walkingmap/131148_Myoshoji_River_Course_(Advanced).zip
                ^^^^^^ → 131148 → 13114 中野区
```

距離まで指標化する場合は各KMLの取得が別途必要。
原著作権者の承諾が得られたコースのみ収録のため、収録は29自治体・264コースにとどまり、残り24自治体は `no_data` になる。

### D6 のURL誤記

カタログに登録されている「優先整備区間（シェープファイル）」のURLはホスト名が `www.kensetsu.metro.tokyo.jg.jp`（`lg` が `jg`）になっており開けない。
`https://www.kensetsu.metro.tokyo.lg.jp/content/000035729.zip` が正しい。datasets.py 側は修正済み。

### 交通量（D2・D3）の自治体割当が未解決

軸1の「交通量」に使う予定の2つは、どちらも自治体コードを持つ列がない。

- **D2（警視庁）**: 集計単位が方面・スクリーンライン・交差点。自治体別に落とすには交差点名からの住所推定が要る。参考扱いにとどめる。
- **D3（センサス）**: 1行1観測地点で、列は路線番号／路線名／地点番号／地点名称と車種別交通量。地点名称（例:「中央自動車道富士吉田線〜中央自動車道」）は区間の記述で住所ではない。

どちらもダウンロード自体はできるので取得対象には残してある。指標化の可否は地点名称からの推定精度しだい。

### ingest の実装で踏んだもの

- **xlsx が zip として展開されてしまう。** `zipfile.is_zipfile()` は xlsx にも True を返す。拡張子が `.zip` のときだけ展開するようにした。
- **zip 内の日本語ファイル名が化ける。** 国内配布の zip は格納名が CP932 のことがあり、`zipfile` はそれを CP437 として読む（`緊急輸送道路.shp` → `ï┘ï}ùAæùô╣ÿH.shp`）。UTF-8フラグが立っていないエントリは読み直してから展開するようにした。

### 大容量ファイルの扱い

次の3件は `make ingest` の既定では取得しない。`--heavy` を渡すか、`--only` でIDを指定したときだけ取得する。

| ファイル | サイズ |
|---|---|
| D4 `03_jurinchi.zip`（樹林地） | 約474MB |
| D13 `R03.zip`（区部） | 約363MB |
| D13 `R04.zip`（多摩・島しょ） | 約309MB |

## 2026-08-13 ODPTの再確認とIDの振り直し

### ODPTの静的データは登録なしで取れる

前日「D10（都営交通）は登録しないと取得先が確定しない」と書いたが、**これは調べ足りなかった。**
ODPTのリソースページに貼られているダウンロードリンクは `api-public.odpt.org` で、認証なしで実データが返る。

| 叩いたもの | 結果 |
|---|---|
| `odpt:Station`（都営地下鉄・都電・日暮里舎人ライナーの駅） | 200 / 149件、緯度経度つき |
| `odpt:BusstopPole`（都営バスのバス停） | 200 / 3,692件、緯度経度つき |
| `ToeiBus-GTFS.zip`（GTFS-JP） | 200 / 9.36MB の実ZIP |

リソースページの文面は「※当データは、開発者サイトでのユーザ登録後、以下のURLからも**アクセス可能です**」で、
トークン付きの `api.odpt.org/...?acl:consumerKey=...` は*追加の*経路だった。登録が要るのはそちらとリアルタイム系（GTFS-RT、ロケーション情報）で、今回の指標にリアルタイムは要らない。

これで出社軸4指標のうち `station_density` と `transit_options` は登録なしで作れる。
残る `commute_time_avg` と `transfer_count_avg` は登録の有無とは別問題で、都営データだけではJR・私鉄を含む所要時間を出せない。

ただし**取得できることと利用条件を確認したことは別**。開発者サイトの利用条件はまだ読んでいないので、D10 は `pending` のままにしてある。
（→ この日のうちに条件を確認して外した。後述の「D10 を `pending` から外した」を参照）

### IDを詰めて振り直した

不採用にしたデータを番号体系から外し、使う18件を D1〜D18 に振り直した。旧D2（自動車騒音）と旧D6（エコロジカル・ネットワークマップ）が抜けた分を詰めている。

不採用データの情報はコードには置かず、[data.md](./data.md) の4節にだけ残す。

あわせて次を直した。

- `indicators.py` から `road_noise_leq`（自動車騒音）を削除。軸1は PM2.5・幹線道路密度・交通量の3指標になった
- `arterial_road_density` の出所を行政区域ポリゴンから D18（緊急輸送道路）へ。`spatial_join.py` のハンドラも同じく付け替え
- `score.py` のダミーデータから `road_noise_leq` を削除

振り直しは `\bD\d+\b` の一括置換で始めたが、**Python の `\b` は日本語を単語構成文字として扱う**ため「D18は」「D12の」のように直後が日本語のものがマッチせず、10箇所が取り残された。
直後が `\w` のものを別途走査して拾っている。同じ手を使うときは注意。

### D10 を `pending` から外した

利用条件を確認した結果、**CC BY 4.0 だった**ので取得先を確定させた。根拠は2つで、どちらも同じ結論を指す。

- ODPTのデータセットページ（例 `ckan.odpt.org/dataset/r_station-toei`）に「本コンテンツ等は CC BY 4.0 の下でライセンスされています」と明記。ページ下部のライセンス欄も CC BY 4.0
- 都カタログのCKAN APIで `t000018d0000000052` を引くと `license_id` が `CC-BY-4.0`

「開発者サイトの利用条件」は CC BY を上書きする別ライセンスではなく、登録が要るのはトークン付きAPIとリアルタイム系という話だった。取得したのは次の2本。

| key | 中身 | サイズ |
|---|---|---|
| `gtfs_bus` | `ToeiBus-GTFS.zip`（GTFS-JP） | 9.1MB（展開後 `stop_times.txt` だけで95MB） |
| `stations` | `odpt:Station`（都営地下鉄・都電・日暮里舎人ライナー） | 139KB / 149レコード |

クレジット表記の様式はODPT開発者サイトのFAQに定めがあるが、**あのページはSPAで `curl` では本文が取れず、文言をまだ確認できていない**。積み残しに回した。

### 数え方の落とし穴を2つ

- **stops.txt はポールと停留所が同居する。** `location_type=0` のポールが3,692件、それを束ねる `location_type=1` の停留所が1,674件。ポールを数えると同じ停留所を上下線で二重に数えるので、`parent_station` が空の行＝停留所だけを数える。ただし系統数を出すときは逆で、`stop_times.txt` が参照するのはポールの `stop_id` なので、ポール → 親停留所 → 自治体 とたどってから数える
- **`odpt:Station` は路線ごとに1レコード。** 149件あるが実駅数は141。新宿・三田・春日など8駅が乗り入れ路線の数だけ重複するので、駅名でまとめる

### ただし都営だけでは軸4を支えられない

実装して自治体に落としたところ、**53自治体中27自治体にしか点が落ちなかった。** 残り26自治体（目黒区＋多摩25市町村）は0件。

さらに厄介なのは、値が出る自治体でも実態とかけ離れることがある点。

| 自治体 | `station_density` | 実態 |
|---|---|---|
| 中央区 | 7.89 件/km² | 妥当 |
| 世田谷区 | 0.05 件/km² | 東急・小田急バスが主体で都営バスがほぼ走らない。私鉄駅は多い |
| 大田区 | 0.29 件/km² | 同上（東急・京急） |
| 目黒区 | データなし | 都営の駅もバス停もないが、東横線・目黒線・日比谷線が走る |

0件の自治体は規約どおり0で埋めず欠損にしてあるが、**問題は欠損側ではなく「値はあるが過小」な世田谷区・大田区のほう**で、これは地図上で「データなし」と区別できない。
`station_density` と `transit_options` をこのまま軸スコアに算入すると、私鉄沿線の区が不当に低く出る。算入するかどうかは要判断として積み残しに入れた。
全域を埋めるなら国土数値情報の鉄道データ（N02）とバス停留所（P11）が候補になるが、データセットの追加になるので別途相談する。
