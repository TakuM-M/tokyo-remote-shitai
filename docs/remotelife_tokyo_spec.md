## 1. 背景・課題

### 1.1 何が起きているか
- コロナ禍以降、リモートワーク／ハイブリッド勤務が定着し、「毎日通勤する前提」で最適化された住まい選びが実態と合わなくなっている
- 一方で、既存の住まい探しサービスの評価軸は **家賃・駅徒歩・沿線・間取り** が中心。「日中ずっと家にいる人」にとっての快適さを測る指標がない
- 「街の住みやすさランキング」系のメディア記事は存在するが、(a) 評価根拠が不透明、(b) 重み付けを変えられない、(c) 更新されない、という問題

### 1.2 リモートワーカー特有の困りごと（仮説）
1. 家が静かか分からない（幹線道路沿い・線路沿いの騒音は内見では気づきにくい）
2. 気分転換に行ける場所が近くにあるか分からない（公園、図書館、散歩コース）
3. 家で集中できない日の逃げ場（サテライトオフィス、図書館の学習席）が近くにあるか分からない
4. 週1〜2回の出社が現実的な範囲か
5. 職場と切り離された地域とのつながりを作れるか（NPO、地域活動の受け皿）

### 1.3 なぜオープンデータで解けるか
上記1〜5はいずれも、東京都がすでに公開しているデータ（騒音、緑、公共施設、サテライトオフィス、交通、NPO）を **市区町村単位に横断集計するだけで近似できる**。
個々のデータは公開済みなのに、「リモートワーカーの視点」で束ねた形では誰も提示していない、というのが本プロダクトの空白地帯。

## 4. スコア設計

### 4.1 全体方針
- **6軸**でスコア化し、各軸 0〜100 に正規化する
- 総合スコア = Σ(軸スコア × ユーザー設定の重み) / Σ(重み)
- 重みの初期値は全軸均等（1.0）。ユーザーがスライダーで 0〜2.0 の範囲で変更可能
- **算出式・元データ・更新日をすべて画面から辿れるようにする（ブラックボックスの回避）**

### 4.2 正規化方法
```
1. 各指標を「面積あたり」または「人口あたり」に換算し、規模の差を除去
2. 上下5パーセンタイルでウィンザライズ（都心の外れ値でスケールが潰れるのを防ぐ）
3. min-max正規化で 0〜100 にスケーリング
4. 「低いほど良い」指標（騒音、PM2.5、地価）は 100 - score で反転
5. 軸内に複数指標がある場合は、指標スコアの単純平均（重み付けは発展課題）
```

### 4.3 6軸の定義

#### 軸1: しずけさ（Quiet）
| 指標 | 定義 | 方向 |
|---|---|---|
| 自動車騒音 | 環境基準達成率 / 測定地点の昼夜等価騒音レベル平均 | 低いほど良 |
| PM2.5 | 大気測定局の年間平均値（自治体内局の平均） | 低いほど良 |
| 幹線道路密度 | 都道の総延長 / 面積 | 低いほど良 |
| 交通量 | 主要地点の平日24時間交通量の自治体平均 | 低いほど良 |

#### 軸2: いきぬき（Refresh）
| 指標 | 定義 | 方向 |
|---|---|---|
| 緑被率 | 緑のオープンデータより、緑地面積 / 総面積 | 高いほど良 |
| 公園密度 | 公園数 / 面積（都立＋区市町村立） | 高いほど良 |
| 散歩コース | TOKYO WALKING MAP 掲載コース数 | 高いほど良 |
| 自転車走行空間 | 整備延長 / 道路総延長 | 高いほど良 |

#### 軸3: しごとば（Workspace）
| 指標 | 定義 | 方向 |
|---|---|---|
| サテライトオフィス | TOKYOテレワークアプリ掲載施設数 / 人口1万人 | 高いほど良 |
| 図書館 | 都立・区市町村立図書館数 / 人口1万人 | 高いほど良 |
| 文化施設 | 生涯学習センター・文化施設数 / 人口1万人 | 高いほど良 |

#### 軸4: しゅっしゃ（Commute）
| 指標 | 定義 | 方向 |
|---|---|---|
| 主要拠点までの所要時間 | 自治体代表駅 → 東京/新宿/渋谷/品川 の最短所要時間の平均 | 短いほど良 |
| 乗換回数 | 同上の平均乗換回数 | 少ないほど良 |
| 駅アクセス | 鉄道駅数 + バス停密度 | 高いほど良 |
| 交通の選択肢 | 都営バス系統数、コミュニティバスの有無 | 高いほど良 |

#### 軸5: くらしのコスト（Cost）
| 指標 | 定義 | 方向 |
|---|---|---|
| 地価水準 | 地価公示（住宅地）の自治体内平均 ㎡単価 | 低いほど良 |
| 住宅の広さ余地 | 土地利用現況調査より、住宅系用途の1棟あたり面積 | 高いほど良 |

#### 軸6: つながり（Community）
| 指標 | 定義 | 方向 |
|---|---|---|
| NPO密度 | 認証NPO法人数 / 人口1万人 | 高いほど良 |
| 地域活動の場 | 公共施設（集会所・コミュニティ施設）数 / 人口1万人 | 高いほど良 |
| 就業構造 | 昼夜間人口比率（低いほど「昼も人がいる住宅地」） | 参考指標 |

## 5. 画面仕様

### 画面1: メインマップ（`/`）
- スライダー操作 → **即座に**（デバウンス200ms）地図の色が再計算・再描画される
- モバイルではサイドバーをボトムシート化

### 画面2: 詳細パネル（自治体クリック時）
- 自治体名、総合スコア、都内順位
- 6軸レーダーチャート（比較用に都平均を重ねて表示）
- 各軸を展開すると、内訳指標の実測値と全体分布内の位置（箱ひげ）を表示
- 各指標に **出典データセット名 + カタログへのリンク + データ更新日** を必ず併記
- 「この自治体を比較に追加」ボタン

### 画面3: 比較モード（`/compare?codes=13104,13208,...`）
- 最大3自治体を横並び
- レーダーチャートの重ね描き + 指標ごとの数値テーブル
- 差が大きい指標をハイライト（「ここが決定的に違う」の提示）
- URLに状態を持たせ、そのまま共有できる

### 6.2 中間データのスキーマ（`municipalities.json`）
```json
{
  "meta": {
    "generated_at": "2026-09-01",
    "version": "0.2",
    "sources": [
      { "id": "D10", "name": "「TOKYOテレワークアプリ」掲載サテライトオフィス一覧データ",
        "org": "東京都産業労働局", "url": "https://catalog.data.metro.tokyo.lg.jp/dataset/t000012d0000000019",
        "license": "CC BY", "updated_at": "2025-xx-xx" }
    ]
  },
  "municipalities": [
    {
      "code": "13104",
      "name": "新宿区",
      "area_km2": 18.22,
      "population": 349000,
      "scores": {
        "quiet": 28.4, "refresh": 51.2, "workspace": 94.7,
        "commute": 98.1, "cost": 12.5, "community": 76.3
      },
      "indicators": {
        "satellite_office_count":   { "value": 55,   "per_10k": 1.58, "score": 96.2, "source": "D10" },
        "pm25_annual_avg":          { "value": 9.8,  "unit": "μg/m3", "score": 31.0, "source": "D1"  },
        "land_price_residential":   { "value": 812000, "unit": "円/m2", "score": 8.4, "source": "D13" },
        "park_density":             { "value": null, "score": null, "status": "no_data" }
      }
    }
  ]
}
```
- **欠損は `null` + `status: "no_data"` とし、0で埋めない**。地図上はハッチング（斜線）で「データなし」を明示する。

### 6.3 データ加工パイプライン
1. [原データ (CSV/GIS/API)]
        ↓  ingest.py（ダウンロード + 生データを raw/ に保存）
2. [raw/]
        ↓  normalize.py（文字コード変換、自治体コード付与、単位統一）
3. [interim/]
        ↓  spatial_join.py（GeoPandas: 点/線データを自治体ポリゴンに集約）
        ↓  score.py（ウィンザライズ → min-max → 軸スコア算出）
4. [municipalities.json]  ← フロントはこれ1本を読むだけ

- フロント側では重み計算のみ行うため、スライダー操作は完全にクライアント完結（高速・サーバ不要）。

## 10. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | 騒音データが全域で揃わない（区市町村ごとの個別公開） | 中核指標が欠ける | 代替として「幹線道路密度 + 交通量」で近似。騒音実測値は取得できた自治体のみ加点表示 |
| R2 | サテライトオフィスデータが許諾施設のみで網羅性に欠ける | 軸3が過小評価 | 図書館・生涯学習センターと合算した「作業できる場所」として設計。網羅性の限界を画面に明記 |
| R3 | 通勤時間の算出に私鉄・JRのデータがない | 軸4の精度低下 | MVPでは駅数・都営路線での近似。発展で駅データ（駅すぱあと等のAPI）を検討 |
| R4 | スコアの重み付けが恣意的に見える | 説得力の欠如 | 全指標の算出式を公開、重みをユーザーが変更可能に、初期値は均等。「唯一の正解」を提示しない |
| R5 | 自治体を序列化する見え方への批判 | 社会実装の障壁 | 「順位」ではなく「相性」の表現を徹底。総合順位より軸ごとの特徴表示を主役にする |
| R6 | データ更新年次がバラバラ（H27〜R7） | 信頼性 | 各指標に更新年を必ず表示。古い指標には注意アイコン |
| R7 | 島しょ部のデータ欠損 | 表示崩れ | 欠損を明示 + 除外トグル。無理に0で埋めない |
| R8 | Day2までにデータ整備が終わらない | デモ不可 | 事前準備でデータ確認を完了させる。軸1・3・4の3軸だけでも成立する設計にしておく |

## 11. 社会実装の方向性

- **都民向け**: 移住・住み替え検討時の判断材料として、都の移住支援情報と接続
- **自治体向け**: 「自分の街の強み・弱み」の客観的な把握ツール。多摩・島しょ部の自治体がリモートワーカー誘致のPR材料として使える
- **都の施策との接続**: 産業労働局のテレワーク推進施策、サテライトオフィス設置補助の効果可視化に転用できる
- **持続性**: サーバレス構成のため維持コストがほぼゼロ。データ更新はCIで自動化可能
- **オープン化**: コードとスコア算出ロジックをMITライセンスで公開し、他道府県への横展開を可能にする
