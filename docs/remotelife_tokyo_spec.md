## 1. 背景・課題

### 1.1 何が起きているか
- コロナ禍以降、リモートワーク／ハイブリッド勤務が定着し、「毎日通勤する前提」で最適化された住まい選びが実態と合わなくなっている
- 一方で、既存の住まい探しサービスの評価軸は **家賃・駅徒歩・沿線・間取り** が中心。「日中ずっと家にいる人」にとっての快適さを測る指標がない
- 「街の住みやすさランキング」系のメディア記事は存在するが、(a) 評価根拠が不透明、(b) 重み付けを変えられない、(c) 更新されない、という問題

### 1.2 リモートワーカー特有の困りごと（仮説）
1. 家が静かか分からない（幹線道路沿い・線路沿いの騒音は内見では気づきにくい）
2. 気分転換に行ける場所が近くにあるか分からない（公園、図書館、散歩コース）
3. 家で集中できない日の逃げ場（サテライトオフィス、図書館の学習席）が近くにあるか分からない
4. 週1〜2回の出社が現実的な範囲か
5. 職場と切り離された地域とのつながりを作れるか（NPO、地域活動の受け皿）

### 1.3 なぜオープンデータで解けるか
上記1〜5はいずれも、東京都がすでに公開しているデータ（大気、道路交通騒音、緑、サテライトオフィス、地価、NPO）を **市区町村単位に横断集計するだけで近似できる**。
個々のデータは公開済みなのに、「リモートワーカーの視点」で束ねた形では誰も提示していない、というのが本プロダクトの空白地帯。

## 4. スコア設計

### 4.1 全体方針
- **5軸**でスコア化し、各軸 0〜100 に正規化する
- 総合スコア = Σ(軸スコア × ユーザー設定の重み) / Σ(重み)
- 重みの初期値は全軸均等（1.0）。ユーザーがスライダーで 0〜2.0 の範囲で変更可能

### 4.2 正規化方法
```
1. 各指標を「面積あたり」または「人口あたり」に換算し、規模の差を除去
2. 分母の小さい自治体で値が跳ねる指標は、全体の中央値に寄せて縮小する
3. 値のある自治体の中でのパーセンタイル順位を 0〜100 に直す
4. 「低いほど良い」指標（騒音、PM2.5、地価）は 100 - score で反転
5. 軸内に複数指標がある場合は、指標スコアの加重平均（重みは指標ごとに定義。
   欠損した指標は重みごと外し、残った指標の重みで正規化する）
```
スコアは値の大きさではなく**都内での順位**を表す。指標ごとに分布の形が大きく違い
（NPO密度・サテライトオフィス密度は上位数自治体だけが極端に大きい）、値をそのまま
min-max にかけると残りの自治体が1桁点に潰れるため。実数は `value` として保持し、
詳細パネルで併記する。

**手順2の縮小**は、分母が小さいために分子が1動いただけで値が振れてしまう自治体を
救うためのもの。檜原村は人口1,747人でNPOが5件しかなく、1件増減するだけで密度が
±5.7件/万人動く。これは下位40自治体が収まっている範囲（1.9〜5.4件/万人）より広く、
28.6件/万人という生の値はほとんど情報を持たないまま全体3位を占めてしまっていた。
そこで「全体の中央値どおりの密度で、分母を *m* だけ余計に観測した」という仮想データを
足してから割り直す。

```
縮小後 = (分子 + 中央値 × m) / (分母 + m)
```

結果は実データと中央値を `分母 : m` の比で混ぜた値になる。分母が *m* より十分大きい
自治体はほぼ動かず、小さい自治体ほど中央値に寄る（NPO密度・*m*=人口5万人のとき、
実データの重みは檜原村3% / 千代田区57% / 世田谷区95%）。閾値で切り捨てるのと違い、
信頼できる度合いに比例して連続的に効く。人口が小さくても件数が十分あれば上位に残る
（千代田区は698件あるので1位のまま）。寄せ先に平均でなく中央値を使うのは、密度の分布が
右に裾を引いていて平均が「ふつう」の位置に無いため（NPO密度は平均6.49に対し中央値4.44）。
縮小は順位づけにだけ使い、`per_10k` などの出力には換算しただけの値を入れる。

### 4.3 5軸の定義

指標の実体は [`data/src/defs/indicators.py`](../data/src/defs/indicators.py)。「カバー」は53自治体のうち値が出ている数（`make missing` の集計）。

#### 軸1: しずけさ（Quiet）
| 指標 | 定義 | 出典 | 方向 | 重み | カバー |
|---|---|---|---|---|---|
| 道路交通騒音 | 幹線道路沿いの測定地点の昼間等価騒音レベル(Leq)を、平成20〜25年度の全地点をまとめて自治体内で平均 | D-quiet-02 | 低いほど良 | 1.0 | 53/53 |

年度をまたいで混ぜるのは、調査地点が毎年入れ替わるため。1年度あたりの地点数は自治体によって1〜40件と幅があり、単年だけを採ると「その年にどの道路を測ったか」がそのまま値になる（奥多摩町は平成25年度の4地点で68.8dB、6年度13地点なら64.5dB）。6年度分3,785地点を使うと1自治体あたり平均71地点になる。値は6年間の平均であって特定年度の状態ではないため、年度ごとの変化を追う用途には使えない。

#### 軸2: いきぬき（Refresh）
外に出て過ごす場所の量（緑・水辺率、公園面積比）と、そこで吸う空気の質（PM2.5）の両方を見る。

| 指標 | 定義 | 出典 | 方向 | 重み | カバー |
|---|---|---|---|---|---|
| 緑・水辺率 | 土地利用細分メッシュ（100m）の田・その他の農用地・森林・荒地・河川地及び湖沼の面積 / 海水域を除く全メッシュ面積 | D-refresh-02 | 高いほど良 | 0.5 | 53/53 |
| PM2.5 | 大気測定局の1分値（2025年6月〜2026年5月）を局ごとに月平均し、各月を等重みで平均した年平均値を自治体内で平均 | D-quiet-01 | 低いほど良 | 0.3 | 43/53 |
| 公園面積比 | 公園緑地のポリゴン面積 / 総面積 | D-refresh-01 | 高いほど良 | 0.2 | 52/53 |

#### 軸3: しごとば（Workspace）
「作業しに行く場所」そのものを数えているのはサテライトオフィスだが、掲載許諾済みの施設しか載らず12自治体が欠損する。図書館は作業専用の施設ではない代わりに53自治体すべてに1館以上あり、その穴を埋める。両者の順位相関は0.35。

| 指標 | 定義 | 出典 | 方向 | 重み | カバー |
|---|---|---|---|---|---|
| サテライトオフィス | TOKYOテレワークアプリ掲載施設数 / 総面積(km2) | D-workspace-01 | 高いほど良 | 0.6 | 41/53 |
| 図書館 | 都内の公立図書館数 / 総面積(km2) | D-workspace-02 | 高いほど良 | 0.4 | 53/53 |

#### 軸4: くらしのコスト（Cost）
| 指標 | 定義 | 出典 | 方向 | カバー |
|---|---|---|---|---|
| 地価水準 | 地価公示（住宅地）の自治体内平均 ㎡単価 | D-cost-01 | 低いほど良 | 51/53 |

#### 軸5: つながり（Community）
「地域に根を張る団体がいくつあるか」（NPO密度）と「実際に開かれている講座・行事がいくつあるか」（社会教育事業）で、測っている側面が違う。順位相関も0.06とほぼ無関係で、どちらを主に置くかを決める根拠が無いため等重みにしている。

| 指標 | 定義 | 出典 | 方向 | 重み | カバー |
|---|---|---|---|---|---|
| NPO密度 | 認証NPO法人数 / 人口1万人（4.2 の縮小あり、*m* = 人口5万人ぶん） | D-community-01 | 高いほど良 | 1.0 | 53/53 |
| 社会教育事業 | 社会教育の学級・講座・事業の年間開催数 / 人口1万人（4.2 の縮小あり、*m* = 人口5万人ぶん） | D-community-02 | 高いほど良 | 1.0 | 53/53 |

## 5. 画面仕様

### 画面1: メインマップ（`/`）
- スライダー操作 → **即座に**（デバウンス200ms）地図の色が再計算・再描画される
- モバイルではサイドバーをボトムシート化

### 画面2: 詳細パネル（自治体クリック時）
- 自治体名、総合スコア、都内順位
- 5軸レーダーチャート（比較用に都平均を重ねて表示）
- 各軸を展開すると、内訳指標の実測値と全体分布内の位置（箱ひげ）を表示
- 各指標に **出典データセット名 + カタログへのリンク + データ更新日** を必ず併記
- 「この自治体を比較に追加」ボタン

### 画面3: 比較モード（`/compare?codes=13104,13208,...`）
- 最大3自治体を横並び
- レーダーチャートの重ね描き + 指標ごとの数値テーブル
- 差が大きい指標をハイライト（「ここが決定的に違う」の提示）
- URLに状態を持たせ、そのまま共有できる

## 6. データ仕様

### 6.1 使用オープンデータ一覧

一覧・取得先・データ構造は [data.md](./data.md)、ライセンス判定は [data_license_check.md](./data_license_check.md)、採否や差替の経緯は [dev_note.md](./dev_note.md) を参照。

### 6.2 中間データのスキーマ（`municipalities.json`）
```json
{
  "meta": {
    "generated_at": "2026-09-01",
    "version": "0.2",
    "sources": [
      { "id": "D-workspace-01", "name": "「TOKYOテレワークアプリ」掲載サテライトオフィス一覧データ",
        "org": "東京都産業労働局", "url": "https://catalog.data.metro.tokyo.lg.jp/dataset/t000012d0000000019",
        "license": "CC BY 4.0（東京都オープンデータ利用規約）", "updated_at": null,
        "notes": "掲載許諾済みの施設のみ収録のため網羅性に限界がある。…" }
    ]
  },
  "municipalities": [
    {
      "code": "13104",
      "name": "新宿区",
      "area_km2": 18.22,
      "population": 349000,
      "scores": {
        "quiet": 28.4, "refresh": 51.2, "workspace": 94.7,
        "cost": 12.5, "community": 76.3
      },
      "indicators": {
        "satellite_office_count":   { "value": 55,   "per_km2": 4.7, "score": 96.2, "source": "D-workspace-01" },
        "pm25_annual_avg":          { "value": 9.8,  "unit": "μg/m3", "score": 31.0, "source": "D-quiet-01" },
        "land_price_residential":   { "value": 812000, "unit": "円/m2", "score": 8.4, "source": "D-cost-01" },
        "park_area":                { "value": 1181952, "unit": "m2", "per_km2": 64871.1, "score": 22.6, "source": "D-refresh-01" },
        "green_coverage_ratio":     { "value": 3.15, "unit": "%", "score": 14.8, "source": "D-refresh-02" }
      }
    }
  ]
}
```
- **欠損は `null` + `status: "no_data"` とし、0で埋めない**。地図上はハッチング（斜線）で「データなし」を明示する（例: 檜原村の `park_area` は原データに1件も無いため `{ "value": null, "score": null, "status": "no_data" }`）。
- 例外として、**原データに調査地点が置かれていないだけで実態は周辺自治体と変わらない欠損**は、根拠を明示した規則にかぎり近隣自治体の値で補完する。補完値は `status: "imputed"` と `imputed_from`（参照した自治体コードの配列）を付けて実測値と区別する。規則は `data/src/defs/imputation.py` に対象・参照・方法・理由をまとめて持つ。
  - 現在の規則は1件。`land_price_residential` の檜原村(13307)・奥多摩町(13308) ← 青梅市(13205)・日の出町(13305) の平均。地価公示に両自治体の調査地点が無く、隣接する西多摩の山間部で住宅地の性格が近いため。
  - 出力例: `{ "value": 93675.0, "score": 96.2, "status": "imputed", "imputed_from": ["13205", "13305"] }`
  - 規則の無い欠損は従来どおり `no_data` のまま。0埋めとの違いは「推定値だと分かる推定値」であること。
- `area_km2` と `population`（全指標の分母）はD-common-01から取る。1ファイルに両方が入っている。

### 6.3 データ加工パイプライン
1. [原データ (CSV/GIS/API)]
        ↓  ingest.py（ダウンロード + 生データを raw/<データセットID>/ に保存）
2. [raw/]
        ↓  normalize.py（文字コード変換、自治体コード付与、単位統一）
3. [interim/]
        ↓  spatial_join.py（GeoPandas: 点/線データを自治体ポリゴンに集約）
        ↓  impute.py（規則にもとづく欠損補完。埋めたセルは imputation_log.csv に記録）
        ↓  score.py（分母換算 → パーセンタイル順位 → 軸スコア算出）
4. [municipalities.json]  ← フロントはこれ1本を読むだけ

- フロント側では重み計算のみ行うため、スライダー操作は完全にクライアント完結（高速・サーバ不要）。
- 1データセットが複数ファイルからなることがあるため、`raw/` はデータセットIDごとのディレクトリになる。いつ・どのURLから・どのハッシュのものを取ったかは `raw/manifest.json` に残す。
